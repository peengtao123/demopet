## 概述

### 什么是事务？

事务（Transaction）是数据库操作的最小工作单元，具有以下 **ACID** 特性：

- **A (Atomicity) 原子性**：事务中的所有操作要么全部成功，要么全部失败回滚
- **C (Consistency) 一致性**：事务执行前后，数据库必须保持一致性状态
- **I (Isolation) 隔离性**：多个事务并发执行时，互不干扰
- **D (Durability) 持久性**：事务一旦提交，对数据的改变就是永久的

### 为什么需要事务管理？

在 Web 应用中，一个业务操作往往涉及多个数据库操作。例如：

```java
// 用户注册并分配角色
public void registerUser(User user, Role role) {
    userService.save(user);      // 操作1：保存用户
    roleService.assignRole(role); // 操作2：分配角色
    
    // 如果操作2失败，操作1应该回滚，否则会产生脏数据
}
```

没有事务管理时，如果操作2失败，操作1已经提交，会导致数据不一致。

## 核心概念

### Spring 事务管理的两种方式

#### 1. 声明式事务（推荐）✅

通过 `@Transactional` 注解实现，基于 AOP（面向切面编程）。

**优点：**
- ✅ 代码侵入性小
- ✅ 配置简单
- ✅ 易于维护

```java
@Service
public class UserService {
    
    @Transactional(rollbackFor = Exception.class)
    public void saveUser(User user) {
        userMapper.insert(user);
    }
}
```

#### 2. 编程式事务

通过 `TransactionTemplate` 或 `PlatformTransactionManager` 手动控制。

**适用场景：**
- 需要细粒度控制事务边界
- 动态决定事务行为

```java
@Autowired
private TransactionTemplate transactionTemplate;

public void saveUser(User user) {
    transactionTemplate.execute(status -> {
        try {
            userMapper.insert(user);
            return true;
        } catch (Exception e) {
            status.setRollbackOnly(); // 手动回滚
            return false;
        }
    });
}
```

## @Transactional 注解详解

### 完整参数说明

```java
@Transactional(
    readOnly = false,                    // 是否只读
    timeout = 30,                        // 超时时间（秒）
    rollbackFor = Exception.class,       // 需要回滚的异常
    noRollbackFor = {},                  // 不需要回滚的异常
    propagation = Propagation.REQUIRED,  // 传播行为
    isolation = Isolation.DEFAULT        // 隔离级别
)
```

### 参数详细说明

#### 1. readOnly（只读事务）

```java
// ✅ 查询操作使用只读事务
@Transactional(readOnly = true)
public User getUser(Long id) {
    return userMapper.selectById(id);
}

// ❌ 写操作不能使用只读事务
@Transactional(readOnly = true)
public void saveUser(User user) {
    userMapper.insert(user); // 会抛出异常！
}
```

**优点：**
- 数据库可以优化查询性能
- 防止意外修改数据
- 某些数据库会对只读事务使用不同的锁策略

#### 2. rollbackFor（回滚规则）

```java
// ✅ 推荐：所有异常都回滚
@Transactional(rollbackFor = Exception.class)
public void saveUser(User user) {
    userMapper.insert(user);
}

// ❌ 不推荐：默认只对 RuntimeException 回滚
@Transactional
public void saveUser(User user) {
    userMapper.insert(user);
}
```

**默认行为：**
- ✅ 会回滚：`RuntimeException` 和 `Error`
- ❌ 不会回滚：Checked Exception（如 `IOException`、`SQLException`）

**最佳实践：** 始终使用 `rollbackFor = Exception.class`

#### 3. timeout（超时控制）

```java
// 如果方法执行超过 30 秒，自动回滚
@Transactional(timeout = 30, rollbackFor = Exception.class)
public void batchProcess(List<User> users) {
    for (User user : users) {
        userService.save(user);
    }
}
```

**适用场景：**
- 批量处理大量数据
- 防止长时间占用数据库连接
- 避免死锁导致的资源浪费

#### 4. noRollbackFor（指定不回滚的异常）

```java
@Transactional(
    rollbackFor = Exception.class,
    noRollbackFor = IllegalArgumentException.class
)
public void saveUser(User user) {
    userMapper.insert(user);
    
    // 这个异常不会导致回滚
    if (user.getName() == null) {
        throw new IllegalArgumentException("用户名不能为空");
    }
}
```

## 事务传播行为

### 7种传播行为详解

#### 1. REQUIRED（默认）⭐

**规则：** 如果当前存在事务，则加入该事务；如果当前没有事务，则创建一个新事务。

```java
@Transactional(propagation = Propagation.REQUIRED)
public void methodA() {
    // 场景1：没有事务 → 创建新事务
    userService.save(user);
    
    // 场景2：已有事务 → 加入现有事务
    methodB(); // methodB 也使用 REQUIRED
}

@Transactional(propagation = Propagation.REQUIRED)
public void methodB() {
    roleService.save(role);
}
```

**特点：**
- 最常用的传播行为
- 保证多个方法在同一个事务中执行
- 任何一个方法抛出异常，整个事务都会回滚

#### 2. REQUIRES_NEW

**规则：** 无论当前是否存在事务，都创建新事务。如果当前有事务，则挂起当前事务。

```java
@Transactional(propagation = Propagation.REQUIRED)
public void methodA() {
    userService.save(user); // 事务1
    
    methodB(); // 事务1 被挂起
    
    // 即使这里抛出异常，methodB 的操作也不会回滚
    throw new RuntimeException("异常");
}

@Transactional(propagation = Propagation.REQUIRES_NEW)
public void methodB() {
    logService.saveLog(log); // 事务2（独立）
}
```

**适用场景：**
- 日志记录（无论主业务是否成功，都要记录）
- 发送通知邮件
- 独立的审计操作

#### 3. NESTED（嵌套事务）

**规则：** 如果当前存在事务，则在嵌套事务内执行；如果没有事务，则创建新事务。

```java
@Transactional(propagation = Propagation.REQUIRED)
public void methodA() {
    userService.save(user);
    
    try {
        methodB(); // 嵌套事务
    } catch (Exception e) {
        // methodB 的回滚不会影响 methodA
    }
    
    // methodA 继续执行
}

@Transactional(propagation = Propagation.NESTED)
public void methodB() {
    roleService.save(role);
    // 如果这里抛异常，只会回滚 methodB 的操作
}
```

**特点：**
- 嵌套事务可以独立回滚
- 外层事务回滚会影响内层事务
- 需要数据库支持 Savepoint（MySQL 支持）

#### 4. SUPPORTS

**规则：** 如果当前存在事务，则加入该事务；如果当前没有事务，则以非事务方式执行。

```java
@Transactional(propagation = Propagation.SUPPORTS)
public User getUser(Long id) {
    return userMapper.selectById(id);
}
```

**适用场景：**
- 可选的事务操作
- 查询方法（有事务就用，没有也不用创建）

#### 5. NOT_SUPPORTED

**规则：** 以非事务方式执行，如果当前存在事务，则挂起当前事务。

```java
@Transactional(propagation = Propagation.NOT_SUPPORTED)
public void generateReport() {
    // 生成报表，不需要事务
    // 如果调用方有事务，会被挂起
}
```

**适用场景：**
- 耗时的非数据库操作
- 文件处理
- 复杂的计算任务

#### 6. MANDATORY

**规则：** 必须在事务中执行，如果当前没有事务，则抛出异常。

```java
@Transactional(propagation = Propagation.MANDATORY)
public void mustInTransaction() {
    // 如果调用方没有事务，会抛出 IllegalTransactionStateException
}
```

**适用场景：**
- 强制要求事务的方法
- 确保方法不会被误调用

#### 7. NEVER

**规则：** 必须以非事务方式执行，如果当前存在事务，则抛出异常。

```java
@Transactional(propagation = Propagation.NEVER)
public void mustNotInTransaction() {
    // 如果调用方有事务，会抛出 IllegalTransactionStateException
}
```

**适用场景：**
- 禁止事务的场景（极少使用）

### 传播行为对比表

| 传播行为 | 当前有事务 | 当前无事务 | 使用频率 |
|---------|----------|----------|---------|
| REQUIRED | 加入事务 | 创建事务 | ⭐⭐⭐⭐⭐ |
| REQUIRES_NEW | 挂起并创建新事务 | 创建事务 | ⭐⭐⭐ |
| NESTED | 嵌套事务 | 创建事务 | ⭐⭐ |
| SUPPORTS | 加入事务 | 非事务执行 | ⭐⭐ |
| NOT_SUPPORTED | 挂起事务 | 非事务执行 | ⭐ |
| MANDATORY | 加入事务 | 抛异常 | ⭐ |
| NEVER | 抛异常 | 非事务执行 | ❌ |

## 事务隔离级别

### SQL 标准定义的隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 说明 |
|---------|-----|----------|-----|------|
| READ_UNCOMMITTED | ✅ | ✅ | ✅ | 最低隔离级别 |
| READ_COMMITTED | ❌ | ✅ | ✅ | Oracle 默认 |
| REPEATABLE_READ | ❌ | ❌ | ✅ | MySQL 默认 |
| SERIALIZABLE | ❌ | ❌ | ❌ | 最高隔离级别 |

### Spring 中的隔离级别

```java
@Transactional(isolation = Isolation.DEFAULT)  // 使用数据库默认
@Transactional(isolation = Isolation.READ_COMMITTED)
@Transactional(isolation = Isolation.REPEATABLE_READ)
@Transactional(isolation = Isolation.SERIALIZABLE)
```

### 并发问题说明

#### 1. 脏读（Dirty Read）

事务 A 读取了事务 B 未提交的数据。

```
时间线：
T1: 事务B 更新余额 1000 → 800
T2: 事务A 读取余额 → 800（脏数据）
T3: 事务B 回滚 → 余额恢复 1000
T4: 事务A 基于错误数据操作
```

#### 2. 不可重复读（Non-repeatable Read）

同一事务中，两次读取同一数据得到不同结果。

```
时间线：
T1: 事务A 读取余额 → 1000
T2: 事务B 更新余额 → 800 并提交
T3: 事务A 再次读取余额 → 800（不一致）
```

#### 3. 幻读（Phantom Read）

同一事务中，两次查询返回的记录数不同。

```
时间线：
T1: 事务A 查询用户列表 → 5条记录
T2: 事务B 插入新用户并提交
T3: 事务A 再次查询用户列表 → 6条记录（出现"幻影"）
```

### 推荐配置

```java
// 大多数场景使用数据库默认隔离级别即可
@Transactional(isolation = Isolation.DEFAULT)

// 如果需要防止不可重复读
@Transactional(isolation = Isolation.REPEATABLE_READ)

// 高并发场景，允许一定程度的不一致以提升性能
@Transactional(isolation = Isolation.READ_COMMITTED)
```

## 最佳实践

### ✅ 应该做的

#### 1. 在 Service 层使用事务

```java
// ✅ 正确：在 Service 层
@Service
public class UserService {
    @Transactional(rollbackFor = Exception.class)
    public void saveUser(User user) {
        userMapper.insert(user);
    }
}

// ❌ 错误：不要在 Controller 层
@Controller
public class UserController {
    @Autowired
    private UserService userService;
    
    @PostMapping("/user")
    @Transactional  // ❌ 不要这样做
    public String save(User user) {
        userService.save(user);
        return "redirect:/users";
    }
}
```

#### 2. 保持事务方法简短

```java
// ✅ 好：事务方法只做数据库操作
@Transactional(rollbackFor = Exception.class)
public void createUser(User user) {
    userMapper.insert(user);
    roleMapper.assignDefaultRole(user.getId());
}

// ❌ 不好：事务中包含耗时操作
@Transactional(rollbackFor = Exception.class)
public void createUserWithNotification(User user) {
    userMapper.insert(user);
    
    // ❌ 发送邮件会很慢，占用数据库连接
    emailService.sendWelcomeEmail(user.getEmail());
    
    // ❌ 调用第三方 API
    smsService.sendVerificationCode(user.getPhone());
}

// ✅ 改进：将非数据库操作移到事务外
public void createUserWithNotification(User user) {
    // 先执行事务
    createUser(user);
    
    // 事务提交后，再执行耗时操作
    emailService.sendWelcomeEmail(user.getEmail());
    smsService.sendVerificationCode(user.getPhone());
}
```

#### 3. 正确使用异常处理

```java
// ✅ 正确：让异常传播
@Transactional(rollbackFor = Exception.class)
public void saveUser(User user) {
    userMapper.insert(user);
    // 如果出错，让异常自然抛出，事务会自动回滚
}

// ❌ 错误：吞掉异常
@Transactional(rollbackFor = Exception.class)
public void saveUser(User user) {
    try {
        userMapper.insert(user);
    } catch (Exception e) {
        e.printStackTrace(); // 事务不会回滚！
    }
}

// ✅ 如果必须捕获异常，要重新抛出
@Transactional(rollbackFor = Exception.class)
public void saveUser(User user) {
    try {
        userMapper.insert(user);
    } catch (Exception e) {
        log.error("保存用户失败", e);
        throw new RuntimeException("保存用户失败", e); // 重新抛出
    }
}
```

#### 4. 为查询操作使用只读事务

```java
// ✅ 查询使用只读事务
@Transactional(readOnly = true)
public List<User> listUsers() {
    return userMapper.selectList(null);
}

// ✅ 分页查询
@Transactional(readOnly = true)
public Page<User> pageUsers(int pageNum, int pageSize) {
    Page<User> page = new Page<>(pageNum, pageSize);
    return userMapper.selectPage(page, null);
}
```

#### 5. 批量操作使用事务

```java
// ✅ 批量插入使用事务
@Transactional(rollbackFor = Exception.class)
public void batchCreateUsers(List<User> users) {
    for (User user : users) {
        userMapper.insert(user);
        // 如果任何一个失败，所有插入都会回滚
    }
}
```

### ❌ 不应该做的

#### 1. 避免自调用导致事务失效

```java
// ❌ 错误：自调用，事务不会生效
@Service
public class UserService {
    
    public void methodA() {
        this.methodB(); // ❌ 直接调用，绕过代理
    }
    
    @Transactional(rollbackFor = Exception.class)
    public void methodB() {
        userMapper.insert(user);
    }
}

// ✅ 解决方案1：注入自己
@Service
public class UserService {
    
    @Autowired
    private UserService self; // 注入代理对象
    
    public void methodA() {
        self.methodB(); // ✅ 通过代理调用
    }
    
    @Transactional(rollbackFor = Exception.class)
    public void methodB() {
        userMapper.insert(user);
    }
}

// ✅ 解决方案2：拆分成两个 Service
@Service
public class UserServiceA {
    
    @Autowired
    private UserServiceB serviceB;
    
    public void methodA() {
        serviceB.methodB(); // ✅ 跨 Service 调用
    }
}

@Service
public class UserServiceB {
    
    @Transactional(rollbackFor = Exception.class)
    public void methodB() {
        userMapper.insert(user);
    }
}
```

#### 2. 不要使用 private、static、final 修饰事务方法

```java
// ❌ 这些方法的事务注解不会生效
@Transactional
private void method1() { ... }

@Transactional
static void method2() { ... }

@Transactional
final void method3() { ... }

// ✅ 必须使用 public
@Transactional
public void method() { ... }
```

**原因：** Spring 使用动态代理实现事务，只能代理 public 方法。

#### 3. 避免大事务

```java
// ❌ 不好：事务太大，包含大量数据处理
@Transactional(rollbackFor = Exception.class)
public void processLargeData() {
    List<Data> dataList = dataMapper.selectAll(); // 可能几十万条
    
    for (Data data : dataList) {
        // 复杂处理逻辑
        processData(data);
        dataMapper.update(data);
    }
}

// ✅ 改进：分批处理
public void processLargeData() {
    int pageSize = 1000;
    int pageNum = 1;
    
    while (true) {
        Page<Data> page = dataMapper.selectPage(
            new Page<>(pageNum, pageSize), null
        );
        
        if (page.getRecords().isEmpty()) {
            break;
        }
        
        // 每批数据在一个事务中处理
        processBatch(page.getRecords());
        
        pageNum++;
    }
}

@Transactional(rollbackFor = Exception.class)
public void processBatch(List<Data> batch) {
    for (Data data : batch) {
        processData(data);
        dataMapper.update(data);
    }
}
```

#### 4. 不要在事务中进行远程调用

```java
// ❌ 不好：事务中包含 HTTP 请求
@Transactional(rollbackFor = Exception.class)
public void createUser(User user) {
    userMapper.insert(user);
    
    // ❌ HTTP 请求可能很慢或失败
    restTemplate.postForObject("http://api.example.com/notify", user, Void.class);
}

// ✅ 改进：使用异步或消息队列
@Transactional(rollbackFor = Exception.class)
public void createUser(User user) {
    userMapper.insert(user);
}

// 事务提交后，异步发送通知
@Async
public void sendNotification(User user) {
    restTemplate.postForObject("http://api.example.com/notify", user, Void.class);
}
```

## 常见问题与解决方案

### 问题1：事务不生效

**症状：** 添加了 `@Transactional` 注解，但异常发生时没有回滚。

**可能原因及解决方案：**

#### 原因1：自调用

```java
// ❌ 错误
@Service
public class UserService {
    public void create() {
        this.save(); // 自调用
    }
    
    @Transactional
    public void save() { ... }
}

// ✅ 解决：通过代理调用
@Service
public class UserService {
    @Autowired
    private UserService self;
    
    public void create() {
        self.save(); // 通过代理
    }
    
    @Transactional
    public void save() { ... }
}
```

#### 原因2：方法不是 public

```java
// ❌ 错误
@Transactional
private void save() { ... }

// ✅ 解决：改为 public
@Transactional
public void save() { ... }
```

#### 原因3：异常被捕获

```java
// ❌ 错误
@Transactional
public void save() {
    try {
        userMapper.insert(user);
    } catch (Exception e) {
        e.printStackTrace(); // 异常被吞掉
    }
}

// ✅ 解决：重新抛出异常
@Transactional
public void save() {
    try {
        userMapper.insert(user);
    } catch (Exception e) {
        throw new RuntimeException(e);
    }
}
```

### 问题2：事务传播行为不符合预期

**症状：** 期望方法在独立事务中执行，但实际上加入了外部事务。

**解决方案：** 明确指定传播行为

```java
// 期望独立事务
@Transactional(propagation = Propagation.REQUIRES_NEW)
public void independentMethod() {
    // 总是创建新事务
}
```

### 问题3：死锁问题

**症状：** 多个事务互相等待对方释放锁，导致系统卡死。

**解决方案：**

1. **统一访问顺序**

```java
// ✅ 所有事务都按相同顺序访问资源
@Transactional
public void transfer(Long fromId, Long toId, BigDecimal amount) {
    // 始终先锁定 ID 小的账户
    if (fromId < toId) {
        Account from = accountMapper.selectById(fromId);
        Account to = accountMapper.selectById(toId);
    } else {
        Account to = accountMapper.selectById(toId);
        Account from = accountMapper.selectById(fromId);
    }
    // 执行转账
}
```

2. **设置超时时间**

```java
@Transactional(timeout = 10, rollbackFor = Exception.class)
public void updateWithTimeout() {
    // 如果 10 秒内无法获取锁，自动回滚
}
```

3. **降低隔离级别**

```java
@Transactional(isolation = Isolation.READ_COMMITTED)
public void readData() {
    // 减少锁竞争
}
```

### 问题4：性能问题

**症状：** 添加事务后，系统性能明显下降。

**解决方案：**

1. **查询使用只读事务**

```java
@Transactional(readOnly = true)
public List<User> list() {
    return userMapper.selectList(null);
}
```

2. **减小事务范围**

```java
// ❌ 不好
@Transactional
public void process() {
    List<Data> data = queryData(); // 查询也在事务中
    updateData(data);
}

// ✅ 好
public void process() {
    List<Data> data = queryData(); // 查询在事务外
    updateDataInTransaction(data); // 只有更新在事务中
}

@Transactional
public void updateDataInTransaction(List<Data> data) {
    for (Data d : data) {
        dataMapper.update(d);
    }
}
```

3. **批量操作优化**

```java
// ❌ 不好：逐条插入
@Transactional

    for (User user : users) {
        userMapper.insert(user); // N 次数据库交互
    }
}

// ✅ 好：批量插入
```

```java
@Service
public class TransferService {
    
    @Autowired
    private AccountMapper accountMapper;
    
    /**
     * 转账：从一个账户扣款，向另一个账户加款
     * 必须保证原子性
     */
    @Transactional(rollbackFor = Exception.class)
    public void transfer(Long fromAccountId, Long toAccountId, BigDecimal amount) {
        // 1. 检查余额
        Account fromAccount = accountMapper.selectById(fromAccountId);
        if (fromAccount.getBalance().compareTo(amount) < 0) {
            throw new InsufficientBalanceException("余额不足");
        }
        
        // 2. 扣款
        fromAccount.setBalance(fromAccount.getBalance().subtract(amount));
        accountMapper.updateById(fromAccount);
        
        // 3. 加款
        Account toAccount = accountMapper.selectById(toAccountId);
        toAccount.setBalance(toAccount.getBalance().add(amount));
        accountMapper.updateById(toAccount);
        
        // 4. 记录交易日志
        TransactionLog log = new TransactionLog();
        log.setFromAccountId(fromAccountId);
        log.setToAccountId(toAccountId);
        log.setAmount(amount);
        transactionLogMapper.insert(log);
        
        // 如果任何一步失败，所有操作回滚，资金不会丢失
    }
}
```

```java
    private OrderMapper orderMapper;

    private OrderItemMapper orderItemMapper;
    
    @Autowired
    private ProductMapper productMapper;
    
    @Autowired
    private InventoryService inventoryService;

     * 创建订单：扣减库存 + 创建订单 + 创建订单项

    @Transactional(rollbackFor = Exception.class)
    public Order createOrder(OrderCreateDTO dto) {
        // 1. 检查并扣减库存
        for (OrderItemDTO item : dto.getItems()) {
            Product product = productMapper.selectById(item.getProductId());
            
            if (product.getStock() < item.getQuantity()) {
                throw new InsufficientStockException("库存不足: " + product.getName());
            }
            
            // 扣减库存
            product.setStock(product.getStock() - item.getQuantity());
            productMapper.updateById(product);
        }
        
        // 2. 创建订单
        Order order = new Order();
        order.setUserId(dto.getUserId());
        order.setTotalAmount(dto.getTotalAmount());
        order.setStatus(OrderStatus.PENDING);
        orderMapper.insert(order);
        
        // 3. 创建订单项
        for (OrderItemDTO item : dto.getItems()) {
            OrderItem orderItem = new OrderItem();
            orderItem.setOrderId(order.getId());
            orderItem.setProductId(item.getProductId());
            orderItem.setQuantity(item.getQuantity());
            orderItem.setPrice(item.getPrice());
            orderItemMapper.insert(orderItem);
        }
        
        return order;
    }
}
```

```java
@Service
public class DataImportService {
    
    @Autowired
    private UserMapper userMapper;
    
    /**
     * 批量导入用户
     * 分批处理，避免大事务
     */
    public ImportResult batchImport(List<UserImportDTO> dataList) {
        ImportResult result = new ImportResult();
        int batchSize = 500; // 每批 500 条
        
        for (int i = 0; i < dataList.size(); i += batchSize) {
            int endIndex = Math.min(i + batchSize, dataList.size());
            List<UserImportDTO> batch = dataList.subList(i, endIndex);
            
            try {
                // 每批在一个事务中处理
                importBatch(batch);
                result.addSuccess(batch.size());
            } catch (Exception e) {
                log.error("批次导入失败: {}-{}", i, endIndex, e);
                result.addFailure(batch.size(), e.getMessage());
            }
        }
        
        return result;
    }
    
    @Transactional(rollbackFor = Exception.class)
    public void importBatch(List<UserImportDTO> batch) {
        for (UserImportDTO dto : batch) {
            User user = convertToUser(dto);
            userMapper.insert(user);
        }
    }
}
```

## 性能优化建议

### 1. 合理使用只读事务

```java
// ✅ 查询操作使用只读事务，数据库可以优化
@Transactional(readOnly = true)
public List<User> listUsers() {
    return userMapper.selectList(null);
}
```

**好处：**
- MySQL 不会对 SELECT 加锁
- 可以使用优化的查询计划
- 减少事务开销

### 2. 减小事务范围

```java
// ❌ 不好：事务范围太大
@Transactional
public void process() {
    List<Data> data = fetchData(); // 耗时查询
    processData(data);             // 复杂计算
    saveData(data);                // 数据库操作
}

// ✅ 好：只在必要时开启事务
public void process() {
    List<Data> data = fetchData();     // 无事务
    processData(data);                 // 无事务
    saveDataInTransaction(data);       // 有事务
}

@Transactional
public void saveDataInTransaction(List<Data> data) {
    for (Data d : data) {
        dataMapper.update(d);
    }
}
```

### 3. 避免在循环中调用事务方法

```java
// ❌ 不好：N 次事务
public void batchUpdate(List<User> users) {
    for (User user : users) {
        updateUser(user); // 每次都开启/关闭事务
    }
}

@Transactional
public void updateUser(User user) {
    userMapper.updateById(user);
}

// ✅ 好：1 次事务
@Transactional
public void batchUpdate(List<User> users) {
    for (User user : users) {
        userMapper.updateById(user);
    }
}
```

### 4. 使用批量操作

```java
// ❌ 不好：逐条插入
@Transactional
public void insertUsers(List<User> users) {
    for (User user : users) {
        userMapper.insert(user); // N 次 SQL
    }
}

// ✅ 好：批量插入
@Transactional
public void insertUsers(List<User> users) {
    userMapper.batchInsert(users); // 1 次 SQL
}
```

### 6. 监控事务性能

```java
// 使用 AOP 监控事务执行时间
@Aspect
@Component
@Slf4j
public class TransactionMonitorAspect {
    
    @Around("@annotation(transactional)")
    public Object monitorTransaction(ProceedingJoinPoint joinPoint, 
                                     Transactional transactional) throws Throwable {
        long start = System.currentTimeMillis();
        try {
            return joinPoint.proceed();
        } finally {
            long duration = System.currentTimeMillis() - start;
            String methodName = joinPoint.getSignature().toString();
            
            if (duration > 1000) {
                log.warn("事务执行过慢: {} 耗时: {}ms", methodName, duration);
            }
        }
    }
}
```

## 总结

### 关键要点

1. **始终使用 `@Transactional(rollbackFor = Exception.class)`** 而不是简单的 `@Transactional`

2. **查询操作使用 `readOnly = true`** 提升性能

3. **在 Service 层使用事务**，不要在 Controller 层

4. **保持事务方法简短**，避免在事务中进行远程调用或耗时操作

5. **注意自调用问题**，事务方法不能通过 `this` 调用

6. **批量操作使用事务** 保证数据一致性

7. **根据业务需求选择合适的传播行为**

8. **监控事务性能**，及时发现慢事务

### 常用配置速查表

```java
// 查询操作
@Transactional(readOnly = true)

// 单个写操作
@Transactional(rollbackFor = Exception.class)

// 批量操作
@Transactional(rollbackFor = Exception.class)

// 独立事务（如日志）
@Transactional(propagation = Propagation.REQUIRES_NEW, rollbackFor = Exception.class)

// 超时控制
@Transactional(timeout = 30, rollbackFor = Exception.class)

// 组合配置
@Transactional(
    readOnly = false,
    timeout = 30,
    rollbackFor = Exception.class,
    propagation = Propagation.REQUIRED,
    isolation = Isolation.DEFAULT
)
```
